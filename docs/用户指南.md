# Photo Organizer 用户指南(简体中文)

本文档面向**非开发者**的一般用户。它告诉你 Photo Organizer 能做什么、怎样安全地首次使用、如何一次性导入照片、如何用自动监听(watcher)功能,以及遇到问题时怎么排查。

> 如果你关心的是这个项目的设计蓝图和当前实现状态,请阅读 [README](../README.md)。
> 本文档只描述**当前代码里真实存在**的命令与行为,不会承诺尚未实现的功能。

---

## 1. 这个工具是做什么的

Photo Organizer 帮你把相机(重点支持 Nikon)导入的照片和视频,从乱七八糟的「收件箱」文件夹整理成**按日期、地点分层的目录树**,例如:

```
目标根/
├── 2026/
│   ├── 2026-08-01_深圳/
│   │   └── RAW/
│   │       ├── DSC_0001.NEF
│   │       └── MOV_0001.MOV
│   └── 2026-08-15_Unknown_Location/
│       └── RAW/
│           └── DSC_0100.JPG
```

它通过读取照片的拍摄时间(EXIF)与 GPS 信息来决定文件放哪里,**文件名不会被改写**,同名冲突会安全地追加 `_1`、`_2` 等后缀。

### 一次「整理」经历的步骤

```
扫描文件 → 读取元数据(拍摄时间/GPS) → 反查拍摄地点 → 规划目标位置 → 执行(复制)
```

命令行中,这套流程有两条命令暴露给你:

- `plan` —— **只读**预览,打印「每张照片会放到哪里」,什么都不做。
- `import` —— 真正执行,默认仍是**只预演不落盘**,加 `--execute` 才复制文件。

还有一条 `watch` 命令用于**自动监听**收件箱(见第 6 节)。

## 2. 最重要的安全原则

这一节请务必先读。

1. **源文件永远不会被修改或删除。** v1 只实现「复制」;移动、软链等模式虽然出现在配置里,但当前**未实现**,遇到会被计为「跳过」,绝不会删除你的源文件。
2. **所有命令默认都是「预演」(dry-run)。** `plan`、`import`、`watch` 默认只打印结果、不写任何文件。真正复制需要你显式加 `--execute`。
3. **复制是原子的、不会覆盖。** 文件先写成一个 `.part-` 开头的临时文件,校验大小一致后才改名为最终文件;如果目标已存在,则直接跳过,绝不覆盖。中途断电/中断最多留下一个可忽略的 `.part-` 临时文件,不会留下「看起来完整其实是半截」的归档。
4. **单个文件失败不会中断整批。** 某一两个文件出问题,其余照常处理,结束时你会看到 `成功 / 失败 / 跳过` 的汇总。
5. **先在独立的测试目录里试。** 第一次使用、或要批量导入大量照片前,请用复制出来的副本做验证,不要在唯一一份原始素材上直接试验(见第 9 节的完整流程)。

> **地点识别需要联网。** 只要照片带 GPS,工具会调用 OpenStreetMap 的在线反向地理编码服务来确定地点名。离线或服务不可用时,**不会报错中断**,而是安全地退回到 `Unknown_Location` 文件夹。

## 3. 安装 / 运行前提与首次配置

### 前提

- **Python 3.12 或更高版本**(项目要求 `requires-python = ">=3.12"`)。
- 一个终端(Windows 下推荐用 WSL / Git Bash 等类 Unix 环境)。
- 地点识别功能需要**能访问互联网**(仅在照片带 GPS 时用到,见第 2 节)。

### 安装

在项目根目录(即包含 `pyproject.toml` 的那个目录)执行:

```bash
python -m venv .venv                # 创建虚拟环境(若仓库未自带)
.venv/bin/pip install -e '.[dev]'   # 安装本工具(含开发工具)
```

安装后,工具的可执行文件就是 `.venv/bin/photo-organizer`。先跑一下确认安装成功:

```bash
.venv/bin/photo-organizer
```

正常会打印一行 `Photo Organizer`。

### 首次配置(可选)

工具自带内建默认值,不配置也能用:

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `inbox` | `~/Pictures/Inbox` | 收件箱(新照片落地的目录,或相机挂载点) |
| `dest_root` | `~/Pictures/Organized` | 整理后的输出根目录 |
| `mode` | `copy` | 归档方式(`copy` / `move` / `symlink`;**v1 只有 `copy` 生效**) |
| `dry_run` | `true` | 默认只规划、不写文件 |
| `log_path` | `logs/photo_organizer.log` | 执行日志文件位置 |

想改这些值,把模板复制一份出来再编辑(**这个文件不会提交到 git**,适合放你自己的路径):

```bash
cp config/local.toml.example config/local.toml
# 然后用文本编辑器修改 config/local.toml
```

例如把输出目录改到自己的照片库:

```toml
inbox = "~/Pictures/Inbox"
dest_root = "~/D/照片库/Organized"
mode = "copy"
dry_run = true
```

规则很简单:配置**文件缺失或某个键缺失时,自动回退到内建默认值**;未知的键会被忽略。也就是说,`config/local.toml` 里只写你想覆盖的项即可。

> 提醒:`import` 和 `watch` 命令允许直接用命令行参数指定目录,不一定非要改配置(见下节)。

## 4. 命令总览

| 命令 | 作用 | 会写文件吗 |
|---|---|---|
| `photo-organizer`(无参数) | 打印工具横幅 | 否 |
| `photo-organizer inspect <照片>` | 查看单张照片的元数据(调试用) | 否 |
| `photo-organizer location-preview <文件或目录>` | 只读预览「每天的主导地点」 | 否 |
| `photo-organizer plan <源目录> <目标根>` | 只读预览完整整理计划 | 否 |
| `photo-organizer import <源目录> <目标根>` | 执行导入(默认只预演) | 默认否;加 `--execute` 复制 |
| `photo-organizer watch [收件箱] [目标根]` | 监听收件箱,新文件自动导入 | 默认否;加 `--execute` 复制 |

所有命令都能用 `--help` 查看完整参数,例如 `.venv/bin/photo-organizer import --help`。

几个说明:

- `inspect` 只支持照片(`.NEF` / `.DNG` / `.JPG` / `.JPEG`),不支持视频。
- `plan` / `import` 的源参数必须是**目录**。
- `location-preview` 可以传单个文件或整个目录,支持用 `--location-name` 手动指定地点名覆盖(仅此命令支持),以及 `--mode archive|detail|admin` 切换地点命名粒度。

## 5. 一次性导入照片

假设你已经把相机照片(或视频)拷进一个目录,例如 `~/Downloads/相机导出`,想整理到 `~/Pictures/Organized`。

### 第 1 步:只读预览

```bash
.venv/bin/photo-organizer plan ~/Downloads/相机导出 ~/Pictures/Organized
```

你会看到扫描数量、每天的地点判断,以及每条「源文件 → 目标位置」的计划。**这一步什么都不写。**

> 可加 `--limit N` 控制列出的动作条数(默认 20);`--location-mode` 切换地点命名粒度。

### 第 2 步:预演导入

```bash
.venv/bin/photo-organizer import ~/Downloads/相机导出 ~/Pictures/Organized
```

不带 `--execute` 时,它同样只做预演,并打印 `Import Preview` 汇总(发现多少文件、成功/失败/跳过数)。**不会创建任何目录、不会复制任何文件。**

### 第 3 步:确认无误后真正导入

```bash
.venv/bin/photo-organizer import ~/Downloads/相机导出 ~/Pictures/Organized --execute
```

加上 `--execute` 才真正把文件复制到目标树,并显示进度条(进度条走 stderr,不会污染可解析的输出;在脚本里或不想看进度可用 `--no-progress` 关掉)。

导入完成后的总结形如:

```
Import
======
Source: ...
Destination: ...
Files discovered: 847
Metadata: 847
Planned: 847
Execution:
execute:
success:847
failed:0
skipped:0
Files copied successfully.
```

之后再去目标目录确认一下树形结构即可。

## 6. 输出目录的组织规则

目标树长这样:

```
目标根/<年份>/<YYYY-MM-DD>_<地点名>/RAW/<原始文件名>
```

- **年份 + 日期**:来自照片的 EXIF 拍摄时间(`DateTimeOriginal`,无则回退 `DateTimeDigitized`,再无则用文件修改时间)。按当天照片的拍摄日期分组。
- **地点名**:来自 GPS 反向地理编码。`import` / `plan` / `watch` 使用 `archive`(归档)命名粒度,面向文件夹——对国内照片,通常取**地级市/市名**(例如「深圳」),对海外照片通常取景区或城市名;中日韩地区会输出中文短名并去掉「市/县/都/府」等后缀。
- **文件类型**:v1 阶段,**RAW、JPEG 照片和视频都放进 `RAW/` 子目录**(未来版本再拆分更多分类)。

### 无法确定地点时,实际行为

- **照片没有 GPS**(相机拍摄时未开启定位,或视频)——当天没有任何 GPS 信息,地点记为 `Unknown_Location`。
- **有 GPS 但反查失败**(离线、服务不可用、无结果)——同样安全回退为 `Unknown_Location`。
- **同一天的照片分布在多个地点、没有明显主导**——记为 `Multi_Location`。
- 只要当天**至少有一张**带 GPS 且能确定地点的照片,当天其余照片(包括视频)都会放进同一地点文件夹。

文件夹名会做安全化处理(空格、非法字符替换为下划线),不会出现无法作为文件夹名的字符。

### 文件名冲突怎么办

工具**不改写文件名**,但会保留原名。如果同一批里出现同名文件(例如两张卡都有 `DSC_0001.NEF`),第二个会自动命名为 `DSC_0001_1.NEF`,依此类推;目标已存在时直接跳过,绝不覆盖。

## 7. 视频处理

- **识别**:扫描器会把 `.mov`、`.mp4` 识别为视频(照片扩展名含 `.nef`/`.dng`/`.jpg`/`.jpeg`/`.arw`/`.cr2`/`.cr3` 等)。
- **拍摄时间**:视频容器通常没有 EXIF,工具**用文件的修改时间**作为拍摄时间,据此归入对应日期。
- **地点**:视频没有 GPS,所以某一天如果**没有任何带 GPS 的照片**,该天的文件夹就是 `Unknown_Location`;如果同一天有带 GPS 的照片确定了地点,视频会一起进那个地点文件夹。
- **去向**:视频和照片一样进 `RAW/` 子目录。

> 注意:`inspect` 命令目前只支持照片,不支持视频。

## 8. 自动监听(watcher)

`watch` 会一直盯着你的收件箱,新文件一出现就自动走同一条整理流程。适合「相机/手机往某个目录倒照片,工具自动归档」的场景。

### 启动

```bash
.venv/bin/photo-organizer watch ~/Pictures/Inbox ~/Pictures/Organized
```

收件箱和目标根两个参数都可以省略,省略时用配置里的 `inbox` / `dest_root`。启动后会打印一行状态(`dry-run` 还是 `execute`)以及状态文件路径。

### dry-run 与 --execute 的区别(重要)

- **默认是 dry-run(预演)**:只打印发现的新文件批次和计划目标,`[batch] dry-run: nothing copied, no state written`——**不复制任何东西,也不写状态文件**。适合先观察它「看到」了什么。
- **加 `--execute` 才真正复制**:此时才会把文件复制进目标树,并把处理结果写入状态文件。

确认自己完全理解行为后,再这样启动:

```bash
.venv/bin/photo-organizer watch ~/Pictures/Inbox ~/Pictures/Organized --execute
```

### 它是怎么工作的(时序参数)

| 参数 | 默认 | 含义 |
|---|---|---|
| `--interval` | 2 秒 | 每多久扫描一次收件箱 |
| `--settle` | 5 秒 | 文件的大小/修改时间要「稳定」多久才算写完 |
| `--quiet` | 30 秒 | 收件箱安静多久后才把稳定文件凑成一「批」处理 |

文件还在写入中(大小/修改时间一直变)时不会被处理;等它稳定、且收件箱整体安静下来,才一次性处理一批。

**首次扫描只是「记基线」**:启动时收件箱里已经存在的文件被当作历史,不会触发处理(除非它们曾在状态文件里被记录为失败/未完成)。

### 如何停止

**按 `Ctrl-C`**。`watch` 支持优雅退出(SIGINT 或 SIGTERM),退出前会把处理进度保存到状态文件,然后打印 `Stopped.`。

### 状态文件(state)的作用

状态文件记录每个已处理文件的:**绝对路径 + 大小 + 修改时间 + 状态**(`done` / `in_progress` / `failed`)。默认位置是:

```
~/.cache/photo-organizer/watch_state.json
```

需要隔离时可用 `--state 路径` 指到别处(例如测试时指向临时文件)。

它保证:

- **重启后不重复处理**:某文件处理成功(`done`)后,即使重启 watcher,只要它的大小和修改时间没变,就不会再次处理或复制。
- **内容变化 = 新版本**:同一个文件被新版本覆盖(大小或修改时间变了),会被当作「新文件」重新处理。
- **失败/中断会自动重试**:复制失败、或处理到一半被中断的文件,状态保持为可重试,下次启动会重新尝试。

> dry-run 模式**不会创建或改动**状态文件;只有 `--execute` 才会写。

## 9. 首次安全验证流程(可直接复制)

把下面这段按你的环境改一下,在**完全隔离的临时目录**里完成一次从预览到真正导入、再到 watcher 的完整走通。全程不碰你的真实照片库,任何一步觉得不对都无损失。

```bash
# 0) 确认工具可用
.venv/bin/photo-organizer

# 1) 建一个隔离的测试环境(临时目录)
TEST=$(mktemp -d -t photo-test.XXXXXX)
mkdir -p "$TEST/inbox" "$TEST/dest"

# 2) 把几张小照片/视频【复制】(不是移动!)到测试收件箱
#    (例:cp ~/Pictures/示例/*.NEF "$TEST/inbox/";cp ~/Pictures/示例/*.MOV "$TEST/inbox/")

# 3) 只读预览:看每张文件会被放到哪
.venv/bin/photo-organizer plan "$TEST/inbox" "$TEST/dest"

# 4) 预演导入:确认什么都不写
.venv/bin/photo-organizer import "$TEST/inbox" "$TEST/dest"

# 5) 确认计划符合预期后,真正复制(只是到临时目标,不是你的照片库)
.venv/bin/photo-organizer import "$TEST/inbox" "$TEST/dest" --execute

# 6) 检查测试目标树,并确认源文件原封未动
find "$TEST/dest" -type f
cmp -s "$TEST/inbox/你的文件名.NEF" <(find "$TEST/dest" -name '你的文件名.NEF' | head -1) && echo "内容一致"

# 7) (可选)测一下 watcher:用独立 --state,先 dry-run 再 execute
.venv/bin/photo-organizer watch "$TEST/inbox" "$TEST/dest" --state "$TEST/state.json"
#    按 Ctrl-C 停止后,再执行:
.venv/bin/photo-organizer watch "$TEST/inbox" "$TEST/dest" --execute --state "$TEST/state.json"

# 8) 验证完,删除临时目录
rm -rf "$TEST"
```

几个判断点:

- 第 3、4 步的预览/预演应**不产生任何文件**(目标根目录甚至不会出现)。
- 第 5 步后,测试目标里应出现 `<年份>/<日期>_<地点>/RAW/` 结构;无 GPS 的素材会进 `Unknown_Location/RAW`。
- 第 5 步后,`$TEST/inbox` 里的源文件应**原封未动**。
- 如果测试素材带 GPS 且你想看地点名,需要联网;离线时它们会进 `Unknown_Location`,这是**正常且安全的回退**,不影响验证其余行为。

验证通过后,把同样的命令换到真实目录(建议仍然先在真实照片的**副本**上试一次),再放心地用于批量导入。

## 10. 常见问题与安全建议

**Q:导入时提示 `skipped:…`,是不是丢了照片?**
不是。`skipped` 最常见的原因是**目标文件已存在**——工具不会覆盖任何已有文件。这也意味着:重复跑同一批导入是安全的,不会产生重复副本。请去目标路径确认文件是否已在。

**Q:某些文件 `failed` 了怎么办?**
单个文件失败不会影响整批。先看执行总结里的 `failed` 数量与日志(`log_path`,默认 `logs/photo_organizer.log`)确认原因(常见:源文件已被移动/删除、权限不足、磁盘满)。把源文件找回来后,可以单独重跑 `import`(目标已成功的会自动跳过,失败的重试)。

**Q:磁盘空间要注意什么?**
工具默认是**复制**,目标盘需要和源文件一样大小的额外空间。整理大批量 Raw 照片前,先确认目标盘的剩余空间足够,否则会中途失败。

**Q:断电/中断了会怎样?**
复制是原子的:先写 `.part-` 临时文件,校验后才改名。中断最多留下几个 `.part-` 开头、点号隐藏的临时文件——它们会被扫描器忽略,可放心手动删除。绝不会留下「看起来完整、实际半截」的归档文件,下次重跑也会正常补齐。

**Q:为什么很多照片进了 `Unknown_Location`?**
因为那些照片没有 GPS(拍摄时未开启定位),或当时无法联网反查地点。这是安全降级,不影响整理本身。可以用 `location-preview` 配合 `--location-name` 手动指定地点名**预览**效果。

**Q:我不小心让 watcher 处理了不想处理的文件?**
先按 `Ctrl-C` 停止。dry-run 没写任何东西,直接换目录即可;若已经 `--execute`,处理记录在状态文件里,删掉对应状态或使用不同的收件箱/目标根重来即可(已复制的文件不会自动删除,需手动处理)。

**安全红线:**

- **永远不要对「唯一一份」的原始素材直接试验。** 先在副本/测试目录上跑通,再对真实数据执行。
- 确认你已经理解 dry-run 与 `--execute` 的区别,再对真实照片库使用 `--execute`。
- 工具只复制、不移动;如果你希望整理后清理源目录,请自己在确认无误后手动处理。

## 11. 附注:开发 / 高级验证

`tests/watch_execute_verify.sh` 是一份**开发者的集成验证脚本**,用来验证 watcher 的 `--execute` 真实复制、状态文件、重启去重等行为。**普通用户不需要运行它**;想深入验证的开发者可以从仓库根目录执行:

```bash
bash tests/watch_execute_verify.sh
```

它全程使用隔离的临时目录和临时 `--state`,并**不会触碰**仓库外受保护的真实数据目录;全部断言通过会自动清理现场,失败则保留现场并给出排查指引。
